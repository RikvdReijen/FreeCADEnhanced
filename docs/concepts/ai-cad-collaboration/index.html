Deviation layers for parallel CAD

Several agents — human and AI — editing one parametric model at once. Git cannot do this, and the reason is not effort. It is that three-way merge assumes stable line identity, and a CAD model's Face6 can quietly become Face9 after an unrelated edit. This works from that failure upward.

§ 01

Why the software answer does not transfer

A .FCStd is a zip of XML plus BREP blobs describing a dependency graph, where feature order is semantic and entity names are assigned by traversal. Every assumption git merge relies on is absent.

Source codeParametric CAD
Unit of changea linea node in a dependency graph
Identitystable — the line's contentunstable — Face6 may become Face9
Ordermostly freeload-bearing — order changes the result
Validityany text is a valid filean edit can make the model unsolvable
Equalitybyte comparisongeometric, within tolerance

Row two is the killer — the topological naming problem. Insert a fillet earlier in the tree and downstream references can silently rebind to different geometry. FreeCAD 1.0 shipped real toponaming resilience work; it reduces the problem, it does not delete it.

Consequence

Any merge strategy that operates on the file is a non-starter. Everything below operates on recorded operations and stated intent, and treats geometry as something to verify against — never something to merge.

§ 02

Four levels of parallelism, not one problem

Conflating these is why the problem looks intractable. Separated, three of the four are tractable and the fourth should be refused outright.

LV 1

Different documents, one assembly

Two agents, two files. Git already handles it. The real coupling is the interface — mating faces, bolt patterns, keep-out volumes — not the bytes.

Solved · needs contracts
LV 2

One document, different bodies

Coupled only through datums and external references. The dependency graph has two nearly disconnected components, so it partitions.

Tractable
LV 3

One body, different features

Both insert into the same tree. Order competes, and each insertion can renumber the topology the other depends on. This is where deviation layers earn their keep.

Hard · the target
LV 4

One feature, one sketch

Two edits to one constraint system. The same constraints can have several valid solutions, and merged constraints are usually over- or under-constrained rather than simply wrong.

Refuse · serialise

A system honest about level 4 is more useful than one claiming to handle it.

§ 03

The layer, borrowed from sculpting

This repository already ships the idea, one domain over. A sculpt layer in src/Mod/XR/xrsculpt/ stores a sparse, weighted, reversible displacement, so a whole modelling pass can be dialled back or muted without losing the strokes underneath.

Lift it from mesh displacement to parametric operations. A deviation layer is a named, replayable set of operations recorded against stable references, carrying its author, its base revision, and — critically — its machine-checkable intent. 

// the document is no longer a file you overwrite
evaluate(base) + Σ apply(layerᵢ)   for enabled layers, in order

Which buys four things a binary-file workflow cannot: muting (see the model without a change, with the work intact), reordering (order is meaning, so trying an order is valuable), attribution at feature granularity, and mergeability — because operations merge where bytes cannot.

Try it: two layers that are individually fine

Enabling both is the case the whole design exists for: two changes, neither wrong, that together leave 0.4 mm of wall. No parametric conflict exists — they touch different features. It is only findable by evaluating the combined model.

§ 04

Anchors: the part that decides whether any of this works

Replayable operations need references that survive a recompute. Three mechanisms, in strict order of preference.

MechanismHowConfidence
Named datum A plane, axis or point created explicitly and named. Stable by construction — agents are expected to create the datum they need rather than picking a face. high
Semantic selector A query, not an index: face(of: "Pad3", normal≈+Z, area: largest). Resolves to exactly one, several, or none. high
Fingerprint Area, centroid in a local frame, surface type, adjacency degree — matched within tolerance. A close runner-up counts as ambiguous, not a win. fallback
Deliberate omission

There is no fourth step falling back to the recorded topological name. Reusing a stale Face6 is the exact bug this design exists to avoid, and it would fail silently and plausibly — the worst available failure mode.

Claims — catching the collision before the work

Before starting, an agent declares what it modifies and what it depends on. Overlapping claims warn; an exclusive claim blocks; a dependency that someone else changes notifies you while you work. This is the cheapest win in the design — detecting the collision before two agents spend an hour diverging beats any merge algorithm.

Each agent also gets its own git worktree: isolated checkout, own build directory, own scratch. The worktree isolates the workspace; the layer captures the change in mergeable form. Different halves of the problem, both needed. A worktree is disposable — the layer is the artefact worth keeping.

§ 05

Five kinds of conflict

A text-merge mindset sees the first three and misses the two that matter most.

ClassWhat it isHandling
ReferenceAn anchor no longer resolves, or resolves ambiguouslyRe-anchor with candidates offered — often mechanical
OrderBoth layers insert at the same tree positionAsk, showing the result of each order
ParametricSame parameter, two valuesPresent both with their stated intents
GeometricNo parametric conflict, but the combined result self-intersects or breaks a clearanceMust be computed — the model has to be evaluated
IntentBoth valid, both satisfy the spec, different approachesHuman decision. Never auto-resolved

A CAD merge can be syntactically clean and physically wrong. Two pockets that each leave 3 mm of wall can together leave 0.4 mm — which is the demo above, and which no diff of any file would ever reveal.

So geometric conflict detection is neither optional nor cheap: it means evaluating merged models, in minutes rather than milliseconds on real assemblies. That cost is the honest price of this design.

§ 06

Assemblies: contracts, not merges

For work across parts, the mechanism is not merge at all. Each part publishes an interface, and neighbours may not violate it. 

{
  "part": "motor_mount",
  "mating":   [ { "name": "face_A", "datum": "MountPlane", "bolts": "M4×4 @ 32mm PCD" } ],
  "keep_out": [ { "name": "shaft_sweep", "shape": "cylinder", "r": 14, "h": 40 } ],
  "envelope": { "bbox": [80, 80, 25] },
  "budget":   { "mass_g": 120, "material": "AlSi10Mg" }
}

Violations are computed continuously, like CI — “bracket now intrudes 2.3 mm into motor_mount:shaft_sweep”. This is the CAD analogue of type checking: cheap, local, always on, and it catches whole classes of integration failure long before assembly.

Changing your own contract is allowed, and is a breaking change — announced to every dependent part, exactly like an API change.

§ 07

Review, provenance, and what agents may not touch

Reviewing a CAD change as a text diff is useless. The review surface is geometric: added and removed volume, changed faces, mass-property deltas, interference against neighbours — shown beside the layer's stated intent.

That pairing is the point. The most common failure of an automated change is not that it is wrong, but that it does something other than what it claimed.

Reviewing from inside the model

This repository already has the machinery: src/Mod/XR puts you inside the model at any scale. Two competing layers show as ghosted variants, muted and unmuted from the wrist menu with the same weight control the sculpt layers use, and an interference is walked around at 1:12 rather than squinted at in a viewport. A merge conflict is one of the few review tasks where being inside the geometry is genuinely better rather than a gimmick.

Pinned parameters

Material specifications, safety factors, regulatory clearances, tolerance callouts on mating features, anything feeding a certification: these are pinned. A layer touching one cannot auto-merge. It escalates, always, regardless of how confident the agent is — which is what the third layer in the demo above is showing.

Provenance

Every layer records author, model identity, session, intent, base revision and validation results. AI_POLICY.md already requires disclosure of AI assistance; at engineering scale the bar is higher — a dimension nobody can account for is a liability, not a style violation.

§ 08

What would actually be hard

Concepts are cheap. These are the parts that would decide whether it works.

  1. Anchor resolution is the whole ballgame. If semantic selectors resolve unreliably, every layer becomes a reference conflict and the system is worse than serialising the work. Prototype this first, before anything else is built.
  2. Geometric conflict detection is expensive. Evaluating merged models on every candidate merge is minutes on real assemblies, not milliseconds.
  3. Constraint solver non-determinism puts level-4 merges out of reach, and the design should keep saying so rather than quietly attempting them.
  4. Intent capture depends on agents being honest. A layer whose stated intent does not match its operations is worse than no intent field, because it invites misplaced trust.
  5. Nobody wants a new file format. This has to work with .FCStd as it is — layers live beside the document, never instead of it. Delete the folder and you have an ordinary project.
